# Домашнее задание № 2. Ansible и PostgreSQL

## Результат

Разработана Ansible-роль `postgres`, которая устанавливает и настраивает PostgreSQL, создаёт пользовательскую базу данных и роли, а также устанавливает и запускает `postgres_exporter`.

Исходные материалы:

- [исходный код решения](hw2/);
- [роль PostgreSQL](hw2/roles/postgres/);
- [playbook](hw2/postgres.play.yml);
- [полная выгрузка терминала](ВыгрузкаТерминала.txt).

Работа выполнена в WSL2 на Ubuntu 26.04.1 LTS. В итоговой конфигурации использованы:

- Ansible 13.1.0 / ansible-core 2.20.1;
- PostgreSQL 18.6;
- postgres_exporter 0.20.1;
- коллекция `community.postgresql`.

## Соответствие требованиям

| № | Требование | Реализация |
|---:|---|---|
| 1 | Установка PostgreSQL | Пакеты `postgresql`, `python3-psycopg2` и `acl` устанавливаются модулем `ansible.builtin.apt` из стандартного репозитория Ubuntu. |
| 2 | Каталог данных | Параметр `postgres__data_dir`, значение по умолчанию `/data/postgres/data`. Каталоги создаются с требуемыми владельцами и правами. |
| 3 | Инициализация кластера | Выполняется `pg_ctl initdb -D {{ postgres__data_dir }}` от пользователя `postgres`. Идемпотентность обеспечена через `creates: {{ postgres__data_dir }}/PG_VERSION`. |
| 4 | Настройка `postgresql.conf` | Параметры передаются словарём `postgres__opts` и применяются модулем `lineinfile`. |
| 5 | Настройка `pg_hba.conf` | Правила передаются списком словарей `postgres__hba`; файл формируется Jinja2-шаблоном. |
| 6 | systemd-служба PostgreSQL | Создаётся и включается служба `postgresql-course.service`, запускающая PostgreSQL из каталога данных роли. Стандартный кластер Ubuntu остановлен и отключён. |
| 7 | Проверка `SELECT 1` | Команда выполняется внутри роли; задача завершается ошибкой, если результат отличается от `1`. |
| 8 | Пользовательские базы | Список задаётся параметром `postgres__databases`; создана база `app_db`. |
| 9 | Пользователи PostgreSQL | Список задаётся параметром `postgres__users`; создан пользователь `app_user`. Пароль берётся из зашифрованного Ansible Vault. |
| 10 | Установка postgres_exporter | Архив скачивается и распаковывается на Ansible-контроллере, бинарный файл копируется на целевой хост. |
| 11 | systemd-служба exporter | Создаётся и включается `postgres-exporter.service`. Для подключения используется отдельная роль `postgres_exporter` с членством в `pg_monitor`. |

Публичные параметры роли находятся в `defaults/main.yml` и имеют префикс `postgres__`. Внутренние переменные находятся в `vars/main.yml` и имеют префикс `__`. Изменения конфигурации и unit-файлов применяются через handlers.

## Запуск

Установка коллекций:

```bash
ansible-galaxy collection install -r requirements.yml
```

Запуск playbook:

```bash
ansible-playbook postgres.play.yml
```

## Проверка systemd-служб

Стандартный кластер PostgreSQL из пакета Ubuntu отключён, вместо него используется собственная служба `postgresql-course.service`. Её работоспособность подтверждается успешным `SELECT 1` и выполнением задач создания базы и ролей.

В исходной выгрузке команда проверки содержала шаблонное имя `postgresql@...`, поэтому первая строка относится к отключённой стандартной службе, а вторая — к exporter:

```text
inactive
active
```

Используемые в решении имена служб:

```bash
systemctl is-active postgresql-course.service postgres-exporter.service
```

## Проверка postgres_exporter

Метрики запрошены через Ansible-модуль `uri` по адресу `http://127.0.0.1:9187/metrics`.

```bash
ansible vm1 -m uri \
  -a 'url=http://127.0.0.1:9187/metrics return_content=true' \
  | grep 'pg_up 1'
```

Из полного ответа exporter:

```text
# HELP pg_up Whether the last scrape of metrics from PostgreSQL was able to connect to the server (1 for yes, 0 for no).
# TYPE pg_up gauge
pg_up 1

postgres_exporter_build_info{goarch="amd64",goos="linux",version="0.20.1"} 1
```

Значение `pg_up 1` подтверждает, что exporter запущен и успешно подключается к PostgreSQL.
